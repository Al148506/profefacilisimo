**Hallazgos del análisis (importantes para futuras revisiones):**

- **Contradicción documental resuelta**: SPEC 02 presuponía `Lesson.Version`, ETag/`If-Match` y

- **Drag & drop pospuesto**: los botones Subir/Bajar cubren el criterio de éxito y son accesibles.
- **Consecuencia clave**: sin intervalos y sin versiones, el MVP **no necesita ninguna columna ni
  tabla nueva**. `Activity.EstimatedDuration` (int?) y `Lesson.EstimatedDuration` (int?) ya existen.
  La única migración (`AddCalculatedLessonDuration`) solo cambia `CK_Lesson_Duration` para admitir
  `0` y rellena los totales existentes.
- **`backend/Api/LessonEndpoints.cs` e `ILessonService.cs` no necesitan cambios**: los contratos
  viajan por el binding existente (`SaveLessonRequest`) y la validación vive en `LessonService`.

  sigue necesitando las dos fases (posiciones temporales) dentro de la transacción. Se mantiene,
  descrito en 3 viñetas en vez de una sección entera.
- Total = suma de duraciones (sin intervalos) ⇒ **el total no depende del orden**. Sirve como
  caso de prueba verificable y simplifica el dominio.
- `POST /api/lessons` debe crear con total `0`, no `null`; `null` queda reservado a datos
  heredados incompletos.

### Siguiente: etapa 5 — escritura (POST/PUT transaccional con el conjunto)

⚠️ **Gotcha de EF Core confirmado con evidencia (bloquea la etapa 5 si se ignora).**
Al añadir actividades nuevas a una clase **ya existente** (estado `Unchanged`), EF **no** las marca
`Added` al descubrirlas por la navegación en `DetectChanges`: como `Activity.Id` es
`ValueGeneratedOnAdd` y la clave ya viene puesta, las marca `Modified` y genera
`UPDATE "Activities" SET ... WHERE "Id" = @p` → 0 filas → `DbUpdateConcurrencyException`.
Medido en el test `ListAndDetailExposeTheCalculatedTotalOrNullWhenIncomplete`:

```
UPDATE "Activities" SET "Content" = @p0, "EstimatedDuration" = @p1, ... WHERE "Id" = @p7   -- ← debería ser INSERT
UPDATE "Lessons" SET "EstimatedDuration" = @p32, "UpdatedAt" = @p33
```

Funciona cuando el padre también es nuevo (`db.Lessons.Add(...)`: el grafo entero entra como `Added`),
por eso `Seed`, `Duplicate` y `PersistenceTests` no lo sufren. El patrón que ya usa el repo para
insertar en una clase existente es añadirlas explícitamente:
`db.Activities.AddRange(first, second)` (ver `DetailsContainOrderedReadonlyActivitiesAndJsonObjectsWithoutOwner`).

**Implicación para la etapa 5**: `LessonService.UpdateAsync` debe marcar como `Added` las actividades
creadas por `Lesson.ApplyActivities`. Dos opciones: (a) capturar los Id existentes antes de aplicar y
hacer `db.Activities.Add` con las que no estaban; (b) cambiar `ApplyActivities` para que devuelva las
creadas (`IReadOnlyList<Activity>`) y hacer `db.Activities.AddRange(...)`. La (b) es más explícita y
evita adivinar; implica tocar la firma ya commiteada de la etapa 2.

### Decisiones de implementación (no reabrir sin motivo)

- **Metadatos en RHF, actividades en `useState`.** El guardado valida el conjunto completo con
  `lessonDraftSchema` antes de enviar, y reparte los `issues` por actividad usando la ruta
  `activities[i].<campo>`.
- **`draftFingerprint` excluye `key`**, porque guardar regenera las claves locales a partir de los
  Ids devueltos y eso no es un cambio del profesor.
- **Los errores se re-validan al editar** (`revalidate`): un mensaje nunca sobrevive al error que
  describe. Solo se re-valida una actividad que ya tenía errores, para no marcar campos que el
  profesor aún no ha intentado guardar. Detectado revisando capturas: sin esto el error se quedaba
  en pantalla tras corregir la duración.
- **Al fallar el guardado se selecciona la primera actividad con error**; la lista ya marca todas.
- **Sin selección automática al cargar** una clase: la lista es la vista principal.
- **Quitar la última fila está deshabilitado** (la regla es 1..50) y **Añadir** se deshabilita en 50.
- **«Agregar actividad» usa un `<select>` de tipo + botón**, no un diálogo.
- `draftFromSaved` usa la columna `Type` como discriminador autoritativo y lanza si el tipo es
  desconocido (violación de contrato, no se reinterpreta el contenido).
