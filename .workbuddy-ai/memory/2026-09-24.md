### Pendiente: el criterio de 390 px (aplazado a integración por decisión del usuario)

- `player-activity-duration` y `player-activity-title` **no son clases**: son `data-testid` de E2E
  (lista «Ganchos estables» de C3). No hay que estilizarlos.
- Para medir el desbordamiento horizontal hace falta navegador real. Receta que funciona:
  1. `docker compose exec -T postgres sh -c 'dropdb --if-exists --force -U "$POSTGRES_USER" pf_e2e && createdb -U "$POSTGRES_USER" pf_e2e'`
  2. Migraciones con `ConnectionStrings__Default` + `Jwt__SigningKey` + `ASPNETCORE_ENVIRONMENT=Development`
     y `dotnet-ef database update --project backend/Infrastructure --startup-project backend/Api --no-build`.
  3. API: `dotnet run --project backend/Api --no-build --no-launch-profile --urls http://localhost:5080`.
  4. `cd frontend && npx playwright test --reporter=list`.
- **Ojo**: la primera ejecución de Playwright falló con `ECONNREFUSED` en el proxy de Vite y un 500
  en `/api/auth/register` porque la API no estaba lista cuando Vite arrancó. La API **sí** funciona
  (201 con `Origin` + `X-Requested-With`; 403 sin ellas: `"Origen de solicitud no permitido."`).
  Arrancar la API antes que Playwright, o dejarla caliente, evita el falso negativo.
- **`netstat`/`taskkill` con PID**: el PID que devuelve `netstat` no siempre es el del proceso dueño.
  Para parar la API de pruebas, matar por nombre (`Get-Process Api | Stop-Process -Force`).
- El spec temporal de verificación se borró (`frontend/e2e/`) y los artefactos de `test-results/`
  se limpiaron. La base `pf_e2e` se dejó creada y migrada.
